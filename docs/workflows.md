# Workflow contracts and checkpoint branching

## Graph definition

A project’s `workflow` is `{ schemaVersion: 1, name, revision, nodes, edges }`. A node has a unique lowercase `id`, a catalog `type`, and `settings`. An edge is `{ from, to, input }`. The output type must match the destination port. All nodes must contribute to exactly one output; exactly one primary input is required. Graphs have at most 64 nodes and 256 edges. Cycles are rejected.

| Node | Input ports | Output | Supported settings |
| --- | --- | --- | --- |
| `input` | none | `design` | project text/image/profile and input review |
| `concept` | `design` | `visual` | `feedback`; image input passes through |
| `views` | `visual` | `views` | `feedback`; text requires front, labeled side, back, three-quarter |
| `consistency` | `views` | `checkedViews` | `enabled`, `onFailure` (`stop` / `continue`) |
| `references` | `design` | `references` | human-approved shared 2D/3D assets and saved render sheets |
| `base` | `design` | `base` | separate project editable-base authorization |
| `model` | `views: checkedViews`, optional `references` | `model` | `instructions` |
| `edit` | `views: checkedViews`, `base`, optional `references` | `model` | `instructions` |
| `refine` | `model` | `model` | `enabled`, `maxIterations` (1–5) |
| `review` | `model` | `reviewedModel` | project preview gate; errors/iteration cap force human review |
| `output` | `model: reviewedModel` | `exports` | validate scene/GLB/render and retain validation JSON |

Consistency and refine settings default to the run’s project snapshot; explicit node settings override those defaults. New projects inspect with `enabled: true, onFailure: "continue"`. The studio’s **Four-view check** maps Off to `enabled: false`, Warn and continue to `enabled: true, onFailure: "continue"`, and Stop on issues to `enabled: true, onFailure: "stop"`. The studio shows workflow overrides and differing saved-run policies. Changing project settings never edits earlier runs or approvals.

New projects default all four optional human review pauses to Off. This skips human quality review, never concept/four-view generation or source/base authorization. Review settings are captured from the project, and cannot be removed by altering a waiting run’s graph. Modeling always saves reference-aligned render evidence so enabling refinement downstream can reuse an unchanged model. Refinement Off skips comparison/revision calls. Stopping for human review, failures and the iteration bound remain visible.

The two built-in presets are generated by `workflowPreset('object' | 'humanoid')`. Saved presets are independent UUID records in `<dataDir>/workflow-presets.json`; duplicate/save never overwrites a built-in or source preset. Home/Studio users can run a preset without opening the editor.

## Durable records

`project.workflowRuns[]` stores a run’s ID, exact graph/revision/hash, accepted input snapshot, implementation source hashes, timestamps, node states, immutable checkpoints and separate review decisions. Files live under `<project>/runs/<runId>/<nodeId>/`. Candidate metadata lives in the shared `versions` collection so HTTP, MCP and the viewer observe the same candidate history.

A checkpoint records its output type, data/data hash, graph revision/hash, implementation hash, effective configuration, settings, dependency checkpoint IDs, source identities and each file’s SHA-256/type. Its `checkpoint.json` is created exclusively and never rewritten. Mutable execution/review status lives in the run, outside that record. Artifact files are written in new node/run directories; refinement copies the scene into its own directory before writing comparisons or revisions. Referenced upstream files are hash-verified before consumption/reuse/export.

Partial failures retain files in `run.artifacts` without fabricating a completed checkpoint. The editor shows these beneath the failed node. A contradictory inspection under Warn and continue preserves its failed report in a checked-views checkpoint and shows a non-blocking studio warning with the original views. Stop on issues preserves its report without producing a checked-views checkpoint. Off skips inspection but still requires all four text-generated views. Invalid/incomplete image evidence and inspection execution/parsing errors always block; no error becomes a passing report. A preservation failure produces no editable-model checkpoint. Usage limits stop the scheduler and block more allowance-consuming work in that server session.

## Fork / resume

1. Select a run and inspect its saved checkpoint.
2. Edit later settings/connections and save the graph. A warning explains descendant invalidation.
3. Choose **Branch from here** on a completed checkpoint.
4. The scheduler recursively validates/reuses that node, its ancestors, and unchanged parallel preparation paths. Its descendants and any invalidated parallel evidence execute into a new run. A branch from a model checkpoint creates a distinct candidate even when no new modeling is needed.

The new run records `parentRunId` and `parentCheckpointId`; reused nodes record `reusedFrom`. Node fingerprints include implementation, settings, relevant project/source state and typed parent identities/fingerprints. Changed input/settings/wiring upstream of the chosen checkpoint is rejected; select an earlier valid checkpoint or start fresh. Downstream changes do not invalidate preceding concept images or an unchanged base. New accepted candidates never overwrite the previous model’s artifacts, review or history.

Waiting approvals must be accepted/rejected before a separate run or fork. MCP cannot make these decisions. A fork cannot inherit an unapproved, rejected, failed or interrupted node as completed. Editing consistency policy cannot turn a failed consistency node into reusable evidence. Changing review settings cannot approve a checkpoint already waiting under its run snapshot. On restart, running nodes/runs become interrupted; completed checkpoints and waiting approvals persist. No generation resumes automatically. Implementation changes invalidate reuse; reject an old waiting run before starting with updated code.

## Complete-base preservation

`POST /api/projects/:id/editable-base` is human-only. It records an inspected library asset/content hash and scope: exact `editableObjects`, optional feature exceptions in `allowChanges` (`armature`, `weights`, `shapeKeys`, `uvs`, `materials`), and `allowNewObjects`. Reference-only/reuse-edit library permission does not authorize a full base edit.

The base node copies the complete source to its own artifact directory, opens it with scripts disabled, packs resources and saves `base.blend`, `baseline.json`, `base.glb` and measured roundtrip evidence. GLB input is inspected before import: unsupported extensions/animations, unnamed or ambiguous nodes, unnamed morphs, nontriangle primitives and unsupported influence layouts block. Imported joint/morph names are checked against the GLB structure. The source hash is checked throughout.

For packed `.blend` and `.glb`, static posed rigs as well as rest poses are supported when measured roundtrip checks pass: one modeling scene, ordinary triangle meshes, relative undriven shape keys, armature skin modifiers and basic Principled materials. Nonidentity bone translation/rotation/scale and parent/child bones do not require a pose reset. The rig must use POSE display/evaluation and retain its supported inheritance and skin settings across GLB. REST display mode blocks because GLB cannot retain Blender’s switch between posed and rest evaluation. Drivers, authored animation, constraints (including bone constraints), NLA tracks, linked data, unconverted modifiers, absolute/driven shape keys and unsupported material nodes/links block with a diagnostic. Basic direct base-color/alpha image textures use active untransformed UVs; more elaborate texture graphs require explicit conversion. The initial export/import is checked before spending modeling allowance. Bone display helper meshes are disabled on import.

Static pose verification uses `static-joints-and-inverse-binds-v1`. The exporter retains original inverse bind matrices and writes current evaluated joint transforms (`export_rest_position_armature=False`, current frame, no animations, no modifier application). It declares the existing armature ancestor explicitly. Import uses `guess_original_bind_pose=True` and the Blender bone-axis convention. A disposable import GLB expresses inverse binds and skin coordinates in the armature frame: for armature world matrix A, inverse bind I becomes I A and position v becomes A⁻¹v. Morph position deltas use the linear part of A⁻¹; normals use the corresponding inverse transpose. Joint transforms and hierarchy stay unchanged. This compensates for Blender’s assumption that inverse binds are armature-relative, without resetting a pose, rebinding, or baking deformation. The importer result is then independently checked against the **original** GLB world-space rest and posed joint matrices, weights and skinned surfaces; the normalized copy never becomes the preservation baseline. Export returns skin positions and inverse binds to their original world-frame semantics. Encoded joint weights and evaluated oriented triangles, including current morph values, are also checked directly against Blender. This prevents establishing an already-rebound or visually changed GLB as a baseline. Export roundtrips additionally compare rest matrices, hierarchy, evaluated joint matrices, skin bindings/weights and evaluated world-space surface corners/normals. Euler/quaternion authoring and local parent bases may differ while representing the same measured matrices; raw `matrix_basis` alone is not an export invariant.

Verified GLB variants include Mixamo-style `mixamorig:Hips` → `mixamorig:Spine`, rest and non-rest static poses, translated/rotated root and armature parents, a positive uniform armature unit scale of 0.01, nonidentity skinned mesh ancestry, and an active relative morph. The optional skeleton reference may name the hip, armature or a higher common ancestor, or be omitted, when joint roots have one unambiguous named armature parent. Only the temporary import copy is canonicalized; source bytes and source joint/skin data remain unchanged. Skinned mesh node transforms are ignored by glTF skin evaluation; Blender represents these meshes beneath the armature with equivalent world-space bind and visible geometry. Explicit dense or sparse inverse bind data is required. Missing binds report `Unverifiable GLB bind frame: explicit inverse bind matrices are required`; an incompatible skeleton reports `Unverifiable GLB bind frame`; transforms Blender cannot reconstruct report `Unverifiable GLB bind/rest after import: <bone>` or `Unverifiable GLB posed joint after import: <bone>`. Singular/nonfinite inverse binds and invalid weights report invalid source data. Armature-local bind scale/shear, a singular armature frame or conflicting shared-joint binds report `Unsupported Blender bind representation` with the affected feature; these are importer/native-rest limitations, not a claim that every such source GLB is invalid. Native edit bones cannot encode independent rest scale/shear, and this path does not claim a metadata-assisted reconstruction of those cases. Rotated nonuniform armature scaling can change exported normals in Blender 5.1.2 and still blocks on measured geometry/evaluation mismatch. Roots without a common named armature parent, ambiguous surface correspondence, nondefault inheritance, disabled/preserve-volume skinning, lost skinning or mismatched poses still block. No pose is cleared, applied as rest, or baked into mesh data. Blender tail lengths and authoring controls remain protected in the saved scene; GLB does not encode them and is not advertised as retaining those authoring controls.

Expression evidence includes vertex-group mask bindings/weights, mute state and evaluated per-vertex deformation from value 0 to 1, with other expressions zeroed and original values restored afterward. Masked shape keys (including empty or missing mask groups) block protected GLB export with the object, expression and group named: this path cannot retain Blender's mask configuration. Explicitly convert to unmasked expressions before authorizing such a base; preservation never silently bakes or drops the mask.

Bone evidence includes rotation/scale inheritance, local-location and relative-parent settings in both scene and GLB comparisons. Changes to protected bones fail candidate validation even when rest geometry and weights match. Bases whose inheritance settings cannot survive GLB export/import block during preparation with an unsupported-roundtrip diagnostic.

Modeling opens a fresh copy of `base.blend`, never just independent meshes. The scene snapshot includes object type/parent (including bone parenting)/transform, geometry/topology, skeleton rest matrices/hierarchy, protected pose basis, pose-vs-rest display state, Blender bone lengths and evaluated visible surfaces, per-vertex skin groups/weights, shape keys/values/relative relationships, UV names/active layers/corner assignments and material assignments/properties/images. Protected objects must remain unchanged. Editable meshes can change geometry/transform; declared feature exceptions apply only to those meshes. New objects require explicit permission. A no-op is rejected.

The final `.blend` and GLB are reopened. Edit comparisons retain raw vertex/corner identity; export comparisons use normalized world-space surfaces, per-position weights/morphs and UV corners because glTF can split vertices at seams and bake skinned mesh transforms. Values use five-decimal rounding and normalized signed zero. Float32 inverse-bind retargeting may cross a rounding boundary: GLB-only surface comparisons require a one-to-one bind-position correspondence within 0.00002 scene units, retain exact oriented topology/weight/UV/material associations, bound rest/posed matrix entries to 0.00002, and bound evaluated positions to 0.00002 scene units and normals to the existing 0.0002 vector error. Ambiguous correspondence fails. Saved-scene comparisons retain exact rounded data; these bounds do not grant edit permissions. This is a bounded preservation check, not a claim about arbitrary animation rigs, every Blender setting or geometric quality. Tail lengths/animation authoring and richer material support are outside this first slice; the full `.blend` copy still retains its source scene. Unsupported format changes block rather than claim success.

The versioned [Issue #40 fixtures and evidence](validation/issue40/README.md) reproduce the earlier hip bind/rest error and measure import, edit, export and repeat-import equivalence. They are glTF-authored synthetic fixtures, not an actual Mixamo-exported sample. `npm run test:workflow-blender` runs these checks and the production Store/workflow path; optional `GEN3D_BROWSER_MIXAMO_FIXTURES=.gen3d/workflow-blender-check/mixamo npm run test:browser` exercises the existing UI with real Blender and a deterministic modeler.

`preservation.json` saves changed feature names, unchanged objects, added objects, scope, before/after hashes, the pose/import strategies and the export roundtrip result. Failed checks remove stale success reports before validating again. Protected-feature failures cannot become accepted/exportable candidates. Refinement validates every edited base scene before selecting it; if a later cycle fails, only its earlier validated model can be offered for mandatory human review.

## HTTP and MCP

- `GET /api/workflows`: catalog and presets; `POST /api/workflows/presets`: duplicate/save.
- `PUT /api/projects/:id/workflow` with `{ graph }`: validate and save a revision.
- `POST /api/projects/:id/runs` with `{}`: start; with `{ runId, checkpointId }`: fork.
- `POST /api/projects/:id/runs/:runId/nodes/:nodeId/review` with `{ decision }`: human Web UI only.
- `POST /api/projects/:id/restore` with `{ versionId }`: restore a validated accepted candidate.
- `GET /api/projects/:id`: shared run/checkpoint/candidate state; artifact URLs use its recorded relative paths.

Project MCP offers `list_workflows`, `save_workflow`, `save_workflow_preset`, `run_workflow`, `get_project`, `get_artifact_image` and `export_model`. Existing lower-level pipeline tools remain for scripted legacy operations; use `run_workflow` for graph execution, durable node checkpoints and both presets. They cannot continue around an active graph’s human review. No MCP tool authorizes an editable base or approves a workflow gate.
